# ГИА — тестирование студентов медицинского колледжа

Django-приложение для проведения первого этапа итоговой аттестации (ГИА) студентов медицинского колледжа. Администратор ведёт специальности, группы и студентов, загружает вопросы тестов из XLSX, настраивает комиссии и печатает раздатки с логинами и паролями. Студенты проходят тестирование в браузере и скачивают персональные отчёты.

> Проект разработан при поддержке [chat.deepseek.com](https://chat.deepseek.com).

## 2. Установка и запуск

### Установка

```bash
git clone https://github.com/jdoe058/gia.git
cd gia

# Виртуальное окружение
python -m venv .venv
source .venv/bin/activate

# Зависимости
pip install -r requirements.txt

# Настройки (скопируйте шаблон и отредактируйте)
cp .env.example .env
```

В `.env` замените `SECRET_KEY` на свой. Сгенерировать можно командой:
```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Примените миграции и загрузите стартовые данные:
```bash
python manage.py migrate
python manage.py loaddata specialties
python manage.py createsuperuser
```

> **Перед первым экспериментом в админке** сделайте бэкап пустой БД — точку «чистого старта». Если что-то пойдёт не так на этапе настройки, вернётесь к ней:
> ```bash
> mkdir -p backups
> sqlite3 db.sqlite3 ".backup 'backups/db_initial.sqlite3'"
> ```

### Запуск

```bash
python manage.py runserver
```
- Приложение (для студентов): http://127.0.0.1:8000/
- Админка (для сотрудников): http://127.0.0.1:8000/admin/

## 3. Возможности системы

### Для администратора (через админку)

- **Специальности:** справочник (6 СПО, загружаются фикстурой).
- **Группы:** настройка курса, вида финансирования, базы (9/11 классов).
- **Студенты:** загрузка списков групп из XLSX. Логины и одноразовые пароли генерируются автоматически.
- **Печать раздатки:** выгрузка списка группы в XLSX (ФИО, логин, пароль) для распечатки и выдачи студентам.
- **Вопросы тестов:** импорт из XLSX на странице специальности. Валидация на ровно один правильный ответ.
- **Комиссии:** ведение состава комиссии (председатель, 3 члена, секретарь) для каждой группы.
- **Маппинг компьютеров:** загрузка файла сопоставления IP-адресов и номеров компьютеров (для указания номера ПК в отчётах).
- **Отчёты:** скачивание сводного отчёта по группе и индивидуальных отчётов студентов прямо из карточки в админке.
- **Сброс тестирования:** возможность удалить результаты, чтобы студент мог пройти тест повторно.

### Для студента (через сайт)

- **Вход в систему:** по логину и паролю, выданным администратором.
- **Прохождение теста:** 
  - Выбирается 80 случайных вопросов по специальности студента.
  - Время на прохождение: 90 минут.
  - Порог для зачёта: 70% правильных ответов.
  - Возможна только одна попытка (до сброса администратором).
- **Результаты:** сразу после теста доступен итог (Зачёт/Незачёт) и разбор ошибок.
- **Скачивание отчёта:** после завершения теста студент может выгрузить свой индивидуальный отчёт в формате XLSX для печати.

## 4. Шаблоны отчётов

Для генерации отчётов используются XLSX-шаблоны с плейсхолдерами. Шаблоны загружаются в систему через админку (раздел «Шаблоны отчётов»).

Поддерживается два типа шаблонов:
- **Индивидуальный** (для отчёта конкретного студента).
- **Сводный** (для отчёта на всю группу).

### Как подготовить шаблон (инструкция для методиста)

1. Сгенерируйте эталонный шаблон командой (или попросите системного администратора):
   ```bash
   python manage.py generate_report_template
   ```
   Файл появится в папке `examples/report_template.xlsx`.
2. Откройте его в Excel или LibreOffice.
3. Оформите шапку по своему усмотрению (добавьте логотип, название учебного заведения). **Не удаляйте** ячейки с текстом вида `{{group_name}}` и `{{data_start}}` — в них программа будет подставлять данные.
4. Загрузите готовый файл в админке:
   - Перейдите в раздел «Шаблоны отчётов» -> «Добавить».
   - Выберите тип (Индивидуальный или Сводный).
   - Загрузите файл.
   - Сохраните.

## 5. Данные и резервное копирование

### Что где лежит

| Что | Где | Что внутри | В git |
|---|---|---|---|
| `db.sqlite3` | корень проекта | Студенты, группы, вопросы, результаты, пользователи | **Нет** |
| `media/` | корень проекта | Загруженные шаблоны отчётов | **Нет** |
| `.env` | корень проекта | `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` | **Нет** |
| `examples/` | папка в репозитории | Выгрузка вопросов и эталонный шаблон | **Да** |

### Полный бэкап

Для сохранения всех данных нужно скопировать БД и папку с загруженными файлами:

```bash
# Бэкап БД (без остановки сервера)
mkdir -p backups
sqlite3 db.sqlite3 ".backup 'backups/db_$(date +%Y%m%d_%H%M).sqlite3'"

# Бэкап загруженных файлов
tar -czf backups/media_$(date +%Y%m%d_%H%M).tar.gz media/
```

**Перед миграциями, импортом вопросов или массовым удалением бэкап обязателен.**

### Восстановление

```bash
# Остановить runserver (Ctrl+C)
mv db.sqlite3 db.sqlite3.broken
cp backups/db_20261031_1430.sqlite3 db.sqlite3

# Если нужно, восстановить файлы
tar -xzf backups/media_20261031_1430.tar.gz
```

## 6. Решение проблем (Troubleshooting)

### `sqlite3: command not found`
Утилита `sqlite3` нужна для бэкапов. Установка:
```bash
sudo apt install sqlite3
```

### `Permission denied: db.sqlite3`
Файл принадлежит другому пользователю. Проверьте владельца:
```bash
ls -l db.sqlite3
# Если нужно, передайте права:
sudo chown youruser:youruser db.sqlite3
```

### `Address already in use`
Порт 8000 занят (возможно, старый runserver не остановился). Запустите на другом порту:
```bash
python manage.py runserver 8001
```

### Отчёт не скачивается / Ошибка «Шаблон не загружен»
Убедитесь, что в разделе админки «Шаблоны отчётов» загружены оба типа шаблонов (Индивидуальный и Сводный).
